Introduction

Welcome to Mini-Project #03! In this mini-project, we will explore patterns of population density within the United States, with an eye towards identifying pockets of high density1 within the US and important ethnic enclaves. You are a freelance travel writer who has been hired to write an entry for a new travel publication, Welcomed by the New Colossus: An Atlas of American Communities. Specifically, the editors have asked you to write a two part story about a demographic group of interest to you: they have given you full discretion to pick the topic, but they want you to discuss both where that ethnic group lives in NYC and where they have concentrated in the broader USA.

NoteChoice of Demographic Group

Despite the title of this assignment, you are not required to focus on a demographic group with which you identify. Feel free to use any demographic group and to disclose as much or as little about yourself as you feel comfortable with while completing this assignment.

Your analysis will principally rely on data from the American Community Survey (ACS), the long-running premier national survey conducted by the US Census Bureau. Unlike the decadal census, which occurs once every ten years, the ACS is constantly collecting new data, giving a up-to-date picture of the American public. ACS data is released across a range of granularities, from national averages to small census-block level estimates. High-level estimates, e.g., those for the country as a whole or individual states, are published on a year-by-year basis, in a data product often called “ACS-1” since they are derived from samples taken in a one-year window. In order to preserve respondent privacy and ensure statistical reliability at finer scales, ACS estimates for smaller regions are published based on a rolling five-year window: these estimates are known as “ACS-5”.2 Larger regions are also available from ACS-5 to avoid alignment issues, but these are a bit less useful to us.

We will combine ACS estimates with data on NYC’s built environment, available to us via PLUTO (Primary Land Use Tax Output), NYC’s primary database of buildings. By giving us additional information about the number of residential units and the total residential square footage within each census block, this will allow us to better understand how population density and demographic concentration relate to residential density in NYC.

Data Acquisition

When downloading data from a web-based resource, it is important to be a polite and responsible user of that resource. Specifically, we want to avoid excessively and repeatedly re-downloading a file if it is not changing. Running a public data source is costly and downloading a file 1,000 times when you only need it once is simply abusing the good will of others.

We can ensure responsible usage by adopting a practice of file caching:

  • Create a “data directory” where data files relevant to the project can be stored
  • When attempting to load a data resource, first see if the relevant file is in the data directory:
    • If the file is in the data directory, simply read and return the contents of that file to the user
    • If the file is not in the data directory, download it into the data directory and save a permanent copy for later use before reading and returning the contents of the file to the user.

This process of “saving” an intermediate result (data file) to avoid an expensive step (downloading) is known as caching. Here, in addition to reducing load on the data server, caching will also make your analysis faster (as you can avoid download times) and allow you to work even when you don’t have reliable internet access.

Review the data download code I provided you in MP#01 and MP#02 to see how I implemented caching there. You should adopt similar patterns for this assignment. In particular, you should consistently:

  1. Check if the results are available locally
  2. If results are not available locally, download and save to a local file
  3. Read results from the saved local file

Note that this pattern should be used for all data access, even if it’s via a package like tidycensus. In addition to being polite, it will also make your analysis run more quickly as you will not be constantly re-downloading large data files. While it is possible to save your results in specialized R data files, I recommend using open and transparent standards like csv (readr::read_csv()) and shp (sf::write_sf()) as appropriate.

Aggregating Tract Data to NTAs

Now that you have NYC’s NTA map, we can aggregate our population counts from tract level to neighborhood level. To do this, we need to join these two data sets together, but this is not a typical join. Because our join is based on ‘is this tract in this NTA?’ rather than (scalar) equality, we need to use a spatial join, which we implement via the sf::st_join function. This join requires a slightly different syntax, including specification of the ‘check’ used to align rows:

  • st_contains: Does the spatial region in the first table contain the points in the second table? (Regions first argument, points second argument)
  • st_intersects: Does a point from the first table fall in a region from the second table? (Points first argument, regions second argument)

These functions are passed (without parentheses or any arguments) as the join argument of st_join. Either of these can work for this step; you simply need to make sure you’re passing the join that corresponds to the order of the tables. A naive join, however, can result in too many rows if a tract crosses multiple NTAs. (This is likely as the Census and the City do not coordinate these boundaries.) We will instead just assign each tract to the NTA with which it has the largest intersection, using the largest=TRUE argument to st_join.

After joining these data sets, we can use st_drop_geometry() to temporarily drop the geometry and summarize our data as usual.6 Finally, we can join our summarized census data with our original NTA data to connect it back to the shape information.

NYC PLUTO - API Usage

Finally, we need to download the PLUTO data from NYC OpenData using the provided API. To access this API, click “Export” near the top right corner of the page, then select “API endpoint”, “Data Format: CSV”, and “Version: SODA2” to get the base URL for this API.

By default, if you simply download directly from that URL you will only get the first 1000 rows in the data set. To download the full data set, you will need to adjust the $limit and $offset parameters in your API call. The

  • $limit controls the number of results returned per query. It defaults to 1000, but can be set much larger than this. Note that you do not necessarily want to set $limit too large as this decreases download times and increases the chance of corruption or time-outs during download.

  • $offset adjusts the results returned from a query. It defaults to 0, returning items 1 to 1000 (at the default $limit of 1000). If you set $offset to 1000, you will instead retrieve rows 1001 to 2000 (at the default $limit of 1000). By iteratively adjusting $offset, you can “page through” the entire data set.

    If there are not $limit results remaining, you will get only as many results as can be returned after the offset. So, in a data set of 1500 observations, a query with $limit=1000 and $offset=1000 will return rows 1001 to 1500. The fact that this is less than $limit can be used to identify the end of the data set.

Using these two query parameters you will be able to download the NYC PLUTO data responsibly.

Data Integration and Initial Exploration

TipTask 6: Exploratory Data Analysis

Answer the following questions to perform your Exploratory Data Analysis of the various data sets used in this project. For each question, answer using inline values, a table, or a graphic as you feel is most effective, though you should plan to have at least: 2 tables, 2 inline values, 1 non-spatial plot, 1 spatial plot among your several answers.

Note that you will need to determine which data sets are best suited to answer each question and may need to return to earlier steps and acquire more data:7 some questions might require joining multiple data sets to answer fully.

  1. Which NYC census tract has the most office floor area in NYC?

    Hint: Use the bct2020 column of the PLUTO data to get census tract ID and the officearea column to get office area. I think you can safely treat NA values in office area as 0s.

  2. Which NYC NTA has the most residential units (unitsses in PLUTO)?

  3. Which NYC census tract has the highest population density, measured as population per square foot of residential space? Do your answers change if you measure by population per residential unit?

  4. What 5 metro areas, other than NYC, have the largest share of population that identify with your ancestry of interest?

  5. At a not-too-granular level, describe the distribution of ancestries in a large non-NYC city of your choosing from the previous question.

  6. As a percentage of all US residents who identify with your ancestry of interest, how many live in NY and how many live in other major metro areas?

    Hint: get_acs(geography="us") will be helpful to get the denominator here.

  7. Do we observe a roughly linear relationship between population and housing (units or area) across NYC tracts or is the relationship more complex?

  8. What are the NTAs with highest buildings? (You can use PLUTO’s numfloors variable as a measure of height. You don’t need to get actual physical measurements.)

  9. Visualize how population density varies across NYC?

  10. How many New Yorkers live in areas that could be described as ‘primarily commercial’? (This one is particularly open-ended.)

There are optional Extra Credit Opportunities where extra points can be awarded for specific additional tasks in this mini-project. The amount of the extra credit is typically not proportional to the work required to complete these tasks, but I provide these for students who want to dive deeper into this project and develop additional data analysis skills not covered in the main part of this mini-project.

Extra Credit Opportunity #01: Interactive Graphics

Possible Extra Credit: Up to 3 Points

One point of extra credit will be awarded to submissions that make effective use of the “interactive” functionality afforded by the ggiraph package in a standard (non-map) graph; an additional point of extra credit will be awarded for use of interactive functionality on a map. (See Lab #07 for examples.) Extra Credit Opportunity #02: Additional Census Tables

Possible Extra Credit: Up to 3 Points

Up to three points of extra credit will be awarded for analyses that use additional (non-ancestry) census data tables in a manner that enriches your final write up.

The Census Data Explorer can help you find relevant tables, but your favorite LLM will likely be more effective than trying to navigate through the census tables directly. I would however, strongly advise you to cross-check things. The specific census table codes are not the kind of data that is well-represented in LLM training data and I have found them to be wrong with surprising regularity.
